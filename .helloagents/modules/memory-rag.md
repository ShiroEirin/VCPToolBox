# memory-rag

## 职责

负责记忆系统、TagMemo、标签处理、向量索引协调和 RAG 检索管线。关键文件包括 `KnowledgeBaseManager.js`、`EPAModule.js`、`EmbeddingUtils.js` 以及相关插件。

## 接口定义

### 公共 API
| 函数/方法 | 参数 | 返回值 | 说明 |
|----------|------|--------|------|
| `KnowledgeBaseManager` | 检索请求、索引上下文 | 检索结果与管理状态 | 统一管理知识库和向量检索管线 |
| `EmbeddingUtils` | 文本输入 | 向量或嵌入处理结果 | 提供嵌入相关辅助能力 |

### 运行时数据边界
| 路径 / 文件 | 类型 | 说明 |
|------------|------|------|
| `dailynote/` | 运行时数据目录 | 日记、记忆与召回原始数据，不应当作稳定源码模块 |
| `VectorStore/` | 运行时数据目录 | 向量索引与检索产物目录 |
| `rag_params.json` | 运行时配置 | RAG 参数与阈值配置 |
| `semantic_groups.json` / `meta_thinking_chains.json` | 运行时数据 | 语义分组与思维链等检索辅助数据 |

## 行为规范

### 记忆检索
**条件**: 对话或插件需要历史语义信息。  
**行为**: 按标签、索引和向量检索策略组合召回内容。  
**结果**: 将相关上下文回注到上层流程。

### 索引维护
**条件**: 新内容进入或索引重建。  
**行为**: 更新标签、嵌入和向量数据，必要时调用 Rust 组件。  
**结果**: 检索数据保持可用。

### 边界约束
**条件**: 调整记忆系统或 RAG 参数。  
**行为**: 区分源码实现、运行时数据目录和管理路由，不把 `dailynote/`、`VectorStore/` 等目录当成稳定源码模块。  
**结果**: 变更评估不会误把运行时数据当代码模块。
