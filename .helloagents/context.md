# 项目上下文

## 1. 基本信息

```yaml
名称: VCPToolBox
描述: 以 Node.js 为核心的 AI 能力增强中间层，集成插件运行时、管理前端与 Rust 向量组件
类型: 服务端应用
状态: 开发中
```

## 2. 技术上下文

```yaml
语言: Node.js / JavaScript, Python, Rust
框架: Express 5, PM2, N-API
包管理器: npm, Poetry
构建工具: npm scripts, cargo
```

| 依赖 | 版本 | 用途 |

| numpy / scipy / sympy | poetry | Python 辅助计算与插件生态 |

## 3. 项目概述

### 核心功能
- 通过 `server.js`、`Plugin.js` 组合提供 AI 中间层主服务。
- 通过 `Plugin/` 目录下的多类型插件扩展检索、工具调用、自动化和内容处理能力。
- 通过 `KnowledgeBaseManager.js` 与 `rust-vexus-lite/` 提供记忆、RAG、标签和向量检索能力。
- 通过 `AdminPanel/` 与 `routes/adminPanelRoutes.js` 提供内嵌管理面板。
- 通过 `WebSocketServer.js`、`FileFetcherServer.js` 支持分布式节点协同和远程文件获取。

### 项目边界
```yaml
范围内:
  - AI 中间层服务
  - 插件运行时与插件协议
  - 管理面板与配套路由
  - 记忆系统、向量检索、分布式协同
范围外:
  - 将 AdminPanel 作为独立前端仓库维护
  - 将运行时数据目录视为稳定源码模块
  - 依赖 CI 单元测试作为主要质量门禁
```

## 4. 开发约定

### 代码规范
```yaml
命名风格: 以驼峰命名和语义化文件名为主
文件命名: 根目录扁平化，按职责找文件而不是按 src 分层找文件
目录组织: 主运行时在根目录，复用模块在 modules/，HTTP 路由在 routes/，插件在 Plugin/
```

### 错误处理
```yaml
错误码格式: 以模块日志和 HTTP 返回为主，未见统一全局错误码体系
日志级别: 运行日志、调试日志、插件侧日志并存
```

### 测试要求
```yaml
测试框架: 当前仓库无正式单元测试体系
覆盖率要求: 未定义
测试文件位置: 零散，package.json 中 npm test 为占位脚本
```

### Git规范
```yaml
分支策略: 未在仓库中定义统一分支流程
提交格式: 未在仓库中定义统一 commit message 规范
```

## 5. 当前约束

| 约束 | 原因 | 决策来源 |
|------|------|---------|
| 根目录保持扁平化运行结构 | 现有启动与装配流程依赖根层文件组织 | 项目现状 |
| 插件契约文件固定为 `plugin-manifest.json` | 加载器依赖 manifest schema 与命名 | 项目现状 |
| 禁用插件通过 `.block` 文件表达 | 这是现有启停语义的一部分 | 项目现状 |
| 不应把 `dailynote/`、`image/`、插件状态目录当作稳定源码 | 这些目录以运行时数据为主 | 项目现状 |
| 当前 CI 不能替代运行验证 | `npm test` 不是有效测试入口 | 项目现状 |

## 6. 已知技术债务

| 债务描述 | 优先级 | 来源 | 建议处理时机 |
|---------|--------|------|-------------|
| 大量核心文件体积偏大，理解与改动成本高 | P1 | 根目录多个大文件 | 触达相关模块时逐步拆分 |
| 测试体系薄弱，很多功能依赖生产式验证 | P1 | package.json 与项目说明 | 进行较大功能改动前补强 |
| 多运行时插件生态复杂，安全边界需要持续梳理 | P0 | Shell、远程执行、抓取类插件 | 涉及安全面时优先检查 |
