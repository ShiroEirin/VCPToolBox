[VCP百科全书] 插件说明——VSearch联网搜索（使用规范）
版本：1.1.0 | pluginType: synchronous | protocol: stdio | timeout: 300000ms

一、插件身份
- name: `VSearch`
- displayName: `VSearch 语义并发搜索器`
- version: `1.1.0`
- pluginType: `synchronous`
- protocol: `stdio`
- timeout: `300000`
- author: `VCP`
- 入口: `node VSearch.js`（Node.js）
- commandIdentifier: `VSearch`

二、核心能力
- 一个极简、高效的语义级并发搜索引擎。支持多种搜索后端（Grounding、Grok、Tavily、KimiSearch），针对特定主题和关键词进行深度检索，返回高质量的参考资料。

三、命令与参数
命令 `VSearch`，参数如下：
- `SearchTopic`（必需，字符串）：检索的目标主题或研究背景
- `Keywords`（必需，字符串）：具体的检索关键词，多个用逗号或换行分隔
- `SearchMode`（可选，字符串，默认 `kimisearch`）：搜索模式。可选值：`grounding`（Google搜索）、`grok`（Grok内置搜索）、`tavily`（Tavily外部搜索）、`kimisearch`（Kimi Search外部搜索）
- `ShowURL`（可选，布尔，默认false）：是否在结果中显示参考来源的完整URL

四、配置参数（configSchema）
| 参数 | 类型 | 说明 |
|------|------|--------|
| VSearchKey | string | 用于访问大模型服务的API Key |
| VSearchUrl | string | 大模型服务的API端点URL |
| VSearchModel | string | Grounding模式直接调用的模型名称（建议具备googleSearch工具能力） |
| GrokModel | string | Grok模式使用的模型名称 |
| TavilyKey | string | Tavily API Key（仅Tavily模式需要） |
| TavilyModel | string | Tavily模式下用于二阶总结的模型名称 |
| MaxConcurrent | integer | 并发执行搜索任务的队列上限 |
| KimiSearchUrl | string | Kimi Search API的基础URL（仅KimiSearch模式需要） |
| KimiSearchKey | string | Kimi Search API的访问密钥（仅KimiSearch模式需要） |
| KimiSearchMaxResults | integer | Kimi Search模式下每个关键词返回的最大结果数（默认5，最大20） |
| KimiSearchIncludeContent | boolean | Kimi Search模式下是否抓取网页完整正文（默认false） |
| SummaryKey | string | Tavily/KimiSearch模式下二阶总结专用的LLM API Key（可选） |
| SummaryUrl | string | Tavily/KimiSearch模式下二阶总结专用的LLM API端点URL（可选） |
| SummaryModel | string | Tavily/KimiSearch模式下二阶总结专用的模型名称（可选） |

六、常见错误
- Invalid URL：后端搜索入口配置异常或URL构造失败
- Key缺失：未配置 `VSearchKey`（Grounding模式）或对应模式的密钥
- 模型不可用：`VSearchModel` / `GrokModel` 无效或无权限
- 超时：关键词过多，建议拆批检索
- 模式配置：KimiSearch模式需配置 KimiSearchUrl 和 KimiSearchKey；Tavily模式需配置 TavilyKey

七、使用/排障边界
- 不同 SearchMode 需要不同的配置项，切换模式前确认对应密钥已填写
- Keywords 支持逗号或换行分隔，并发检索后合并结果
- ShowURL 设为 true 会增加返回 Token 消耗
