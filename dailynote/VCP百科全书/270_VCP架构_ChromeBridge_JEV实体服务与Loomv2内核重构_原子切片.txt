一、jevEntityService.js 的安全边界（头两行原文）

```js
// ChromeBridge transport boundary: never expose an unrestricted Jev proxy.
const ALLOWED_COMMANDS = new Set([
    'page_click', 'page_type', 'page_set_value', 'page_send_keys',
    'page_select_option', 'page_hover', 'page_check', 'page_scroll',
    'page_wait_for', 'page_query_html'
]);
```

**白名单只有 10 条页面级命令**，全部是「对已渲染页面做原子操作」，不含任何导航、脚本注入、文件或系统能力。这是本轮最重要的一条安全事实：JEV 通过 ChromeBridge 能做的事被硬编码枚举封死，不是开放式代理。

二、入参校验（实测）

```js
if (typeof data.requestId !== 'string' ||
    !/^[a-zA-Z0-9-]{1,100}$/.test(data.requestId) ||
    Buffer.byteLength(JSON.stringify(data), 'utf8') > 32768) {
```

三重限制：
1. `requestId` 必须是字符串；
2. 必须匹配 `^[a-zA-Z0-9-]{1,100}$`——只允许字母数字与连字符，长度 1–100；
3. 整个 payload 的 UTF-8 字节数 **≤ 32,768**（32KiB）。

三、连接与并发治理

```js
const connections = new WeakMap();
let active = 0;
```

- `connections` 用 **WeakMap** 按 entry 绑定，连接断开后自动回收，不产生泄漏；
- `active` 计数器控制并发；
- 回包前检查 `socket.readyState !== 1`，非 OPEN 直接丢弃；
- `send` 包在 `try { } catch { }` 内，注释原文：「A closed transport must not escape the async handler.」——**关闭的传输层不允许把异常抛出异步处理器**。

回包格式固定：

```json
{ "type": "jev_entity_result", "data": { "requestId": "...", ...result } }
```

四、web-agent-entity-arbiter.js（新增 61 行）

八、风险

1. **白名单是硬边界**：想让 JEV 做白名单外的页面操作，必须改 `ALLOWED_COMMANDS` 源码，不存在配置项绕过——这是刻意设计。
2. **32KiB payload 上限**：`page_type` 粘贴大段文本会超限，需分段。
3. **双仓同名文件**：ToolBox 与 VCPChat 各有一份 webcore 实现，版本漂移会导致协议不匹配。合并上游时若只更新一侧，需手动核对另一侧。
4. `active` 计数器与 `WeakMap` 的组合意味着并发上限由调用侧控制，服务本身不设硬闸（与 `native_rerank.rs` 的 `Semaphore` 不同）。
