# 一、ingestionPipeline.js 派生失效语义收紧（dc50fbb0）

- **新 Tag 摄取路径禁止扫派生表**：原先 `INSERT ... ON CONFLICT(name) DO UPDATE SET vector=excluded.vector` 会在事实写事务中执行 4 条 DELETE（tag_pair_similarity / tag_pair_similarity_status / tag_intrinsic_residuals / tag_intrinsic_residual_status）做"以防万一"式失效。新逻辑改为：此路径**只创建尚不存在的新 Tag**（黑名单已在提取阶段过滤、向量化失败项不落库），新分配的 ID 不可能存在历史 Pairwise/IR 派生记录，因此禁止在事实写事务中扫描大型派生表做无效失效。
- **INSERT 改为纯插入 + lastInsertRowid 取 ID**：`INSERT INTO tags (name, vector) VALUES (?, ?)`（无 ON CONFLICT 更新分支），`const id = Number(inserted.lastInsertRowid)` 替代原先二次 `SELECT id FROM tags WHERE name=?`。
- **已有 Tag 的真实向量替换**必须走专用维护路径，并在那里标脏或精确失效（V9.1 失效钩子职责上收）。

# 二、schemaManager.js 反向端点索引（dc50fbb0 + b13428a5）

- tag_pair_similarity / tag_pair_similarity_status 的主键只覆盖 tag_a 左前缀；新增反向端点索引 `idx_pair_sim_tag_b`、`idx_pair_sim_status_tag_b`，保证按任一 Tag 枚举或失效无向 Pair 时不会退化为全表扫描。
- b13428a5 为该索引迁移补可视化日志：启动时检测 sqlite_master 中缺失的反向索引，`🧱 Building missing Pairwise reverse endpoint index(es): ...` 警告大库构建耗时 + `✅ ... migration complete, elapsed=Xms` 完成日志（前端日志联动，用 Date.now() 计时）。
