# 一、定位

Rust 编写的跨平台原生"语音输入焦点与快捷键 sidecar"。解决 Windows 语音听写（Win+H）在 Electron 应用中无法自动唤起/无焦点反馈的问题：由原生进程负责按键注入与焦点仲裁，Electron 主进程通过 stdin/stdout JSON 行协议与之通信。package.json 的 build 脚本已改为 `node rust_chat_data_service/build-runtime.js && node rust_voice_input_engine/build-runtime.js`（两个 Rust 运行时都要构建）。

# 二、引擎本体（rust_voice_input_engine/）

- Cargo.toml：name `vcp_voice_input_engine`，version 0.1.0，edition 2021，描述"VCP cross-platform native voice input focus and shortcut sidecar"。依赖 serde/serde_json；Windows 目标段条件依赖。
- src/main.rs（963行）两种输入模式：
  - `windows_voice_typing`（别名 win_h，code 1）：注入 Win+H 唤起系统语音输入。
  - `right_alt_hold`（别名 right_alt，code 2）：按住右 Alt 触发听写，HOTKEY_POLL_MS=12ms 轮询，RIGHT_ALT_WATCHDOG_MS=15秒看门狗。
  - 全局状态：OUTPUT_LOCK 输出互斥、CONFIGURED_HOTKEY_VK、HOOK_KEY_PRESSED 原子量；mpsc channel + 线程模型。
- 运行时产物：`runtime/win32-x64/vcp_voice_input_engine.exe`（随仓库分发）。
- 测试脚本：test-right-alt.ps1（192行），支持 ScanCode/VirtualKey 两种注入模式、50-30000ms 时长等参数。

# 三、Electron 侧接入

- **modules/voice/voice-input-engine-adapter.js**（361行）`VoiceInputEngineAdapter` 类：spawn 子进程 + readline 逐行解析 JSON 事件；DEFAULT_REQUEST_TIMEOUT_MS=5000、DEFAULT_READY_TIMEOUT_MS=10000；pendingRequests Map 按序号管理请求；lifecycleState 状态机（stopped→...）；事件监听器 Set；startPromise 防 double-start。
