五、设备管理根权限（9c0cc72 核心新增）
- 持久化：`device-permissions.json` 位于 `appDir(appId)/device-permissions.json`（devicePermissionsPath，821 行），结构 { schemaVersion:1, grants:[{deviceType, origin, fingerprint, name, grantedAt}] }
- 授权函数（以源码实际为准）：
  - loadDevicePermissionGrants(appId)（858）：读取并过滤 deviceType ∈ ['hid','usb','serial'] 且 origin/fingerprint 为字符串的授权；自动 normalizeDeviceOrigin 与 normalizeStoredDeviceFingerprint（兼容旧版含 name/collections 的指纹格式，下次写入自然迁移）
  - saveDevicePermissionGrants(instance)（886）：writeJson 落盘
  - hasDevicePermission(instance, deviceType, origin, device)（893）：按 deviceType + 归一化 origin + 指纹三要素精确匹配
  - grantDevicePermission(instance, deviceType, origin, device, name='')（903）：先写实例内 grants 再 await 落盘——注释明确"选择回调返回给 Chromium 之前必须完成持久化，否则 requestDevice() 已成功但紧随其后的刷新可能早于授权文件落盘"
  - revokeDevicePermission(instance, deviceType, origin, device)（930）：filter 移除，变化时异步落盘（失败仅 console.warn）
- 设备指纹（deviceFingerprint，833）：JSON{type, vendorId(vendorId??usbVendorId), productId(productId??usbProductId), serialNumber}；源码注释：Chromium 的设备选择事件与刷新后的 device permission 回调不保证提供相同的展示字段和 HID collections，只使用跨枚举稳定的硬件标识，deviceId、名称、collections 均不参与持久授权匹配
- 授权中介 configureDevicePermissionBroker(instance)（948）：
  - setPermissionCheckHandler / setPermissionRequestHandler / setDevicePermissionHandler：仅 ['hid','usb','serial'] 且 isAllowedHardwareOrigin(instance, origin) 通过（允许集合 = startUrl origin + 当前 URL origin）
  - protocols 表（hid/usb/serial）：selectEvent / addedEvent / removedEvent / revokedEvent 对（select-hid-device、select-usb-device、select-serial-port 等）；onRevoked 自动 revokeDevicePermission
  - bluetooth：contents.on('select-bluetooth-device')，仅候选发布 + 选择，不进入持久授权（WebBluetooth 无 getDevices()，不能靠盲目刷新确认）
  - 候选通过 sendToShell(instance, 'loom:device-candidates', {protocol, devices:[{id,name,detail}]}) 推给设备中心；instance.pendingDeviceSelections(Map) 管理挂起选择（finish/cancel）
- 壳交互链路（shell-action IPC，2028 起）：
  - 'device-menu' → instance.deviceMenuOpen = payload===true 并 updateViewBounds（deviceMenuView 是后 addChildView 的原生 View，位于网页 View 上方，可真正覆盖网页，见 1427-1430）
  - 'device-request' → requestDeviceFromShell(instance, protocolId)（1151）：向页面注入 navigator.hid.requestDevice({filters:[]}) / navigator.usb.requestDevice / navigator.serial.requestPort / navigator.bluetooth.requestDevice 脚本；requestState(committed 标记) 防旧异步结果覆盖已授权状态
  - 'device-select' → selectDeviceFromShell(instance, {protocol, deviceId})（1249）：对 hid/usb/serial 先 grantDevicePermission 落盘，持久化失败则 pending.finish('') 取消 Chromium 选择并抛"设备授权持久化失败"，避免半提交；随后发送 connected 通知并 finish(deviceId) 提交给 Chromium
  - 设备中心 UI（device-menu.html）：protocols 页签 [['hid','HID'],['usb','USB'],['serial','串口'],['bluetooth','蓝牙']]；api.shellAction('device-request'/'device-select')、api.onDeviceCandidates(renderCandidates)；关闭按钮 api.shellAction('device-menu', false)
- 加载链：manager/shell 与 deviceMenuView 共用 preloads/loom.js（deviceMenuView webPreferences 含 preload + contextIsolation + sandbox，见 1372-1381）；页面 WebContentsView 使用 preloads/loom-page.js + `--loom-page-profile=` 附加参数（1358-1371）

- initializeWebAgentRuntime(instance, generation)（515）：executeJavaScriptInIsolatedWorld(WEB_AGENT_WORLD_ID=999) 注入 3 个源码文件 + bootstrap.js（globalThis.__vcpLoomWebAgentRuntime = core.createWebAgentPageRuntime({window,document,Node}, {runtimeInstanceId:`loom-${appId}-${generation}-${Date.now()}`, redactSensitiveDom:true})），再读 identity 并 instance.webAgentAdapter.updateDocumentState(identity)；成功置 instance.webAgentReady=true

- executeIsolatedPageOperation(instance, action, params, request)（622）：ISOLATED 世界执行 runtime.execute(action, params, {targetContext,...})，url 形如 `vcp-loom-webcore://action/<action>.js`
- executeWebAgentAction(appId, actionId, params, options)（648）：走后端运行时 instance.webAgentRuntime.execute({command, targetContext:{adapter:'electron-loom', targetId:webContents.id, appId}, params, options, metadata:{source:'LoomController', loomAppId}})；response.status===protocol.Status.ERROR 时抛 code/details 结构化错误

八、竟态加固（339a6f3，以源码实际为准）
- 文档代际 documentGeneration：did-start-navigation（主帧非原地）时 +1、loading=true、webAgentReady=false、重建 documentReadyPromise、webAgentAdapter.invalidateDocument()（1471-1478）；waitForDocumentReady / initializeWebAgentRuntime 各关键步骤后校验 generation，失配抛 code='LOOM_DOCUMENT_CHANGED'，放弃旧文档的初始化结果
- did-finish-load（1492）：Promise.allSettled([applyInjections, ensureWebAgentRuntime, captureRenderedSnapshot]) 三者互不阻塞；仅当 generation 仍匹配且错误码非 LOOM_DOCUMENT_CHANGED 才置 webAgentReady=false
- 实例初始化串行化：ensureWebAgentRuntime 用 instance.webAgentInitializationPromise 合并并发调用，finally 中仅当仍是当前 promise 才清空
- 设备侧防竞态：pendingDeviceSelections(Map) 挂起选择统一 finish/cancel 生命周期；deviceRequestStates committed 标记——选择提交后旧 executeJavaScript 的 then/catch 结果一律忽略（页面刷新导致旧上下文销毁的 rejection 不覆盖"已授权"状态）；grantDevicePermission 落盘先于 Chromium 选择回调；selectDeviceFromShell 持久化失败即取消选择防半提交；requestDevice 完成后不主动 reload（厂商站点会自行重建/刷新控制应用，再次 reload 会销毁新页面刚打开的 HID/USB/Serial 句柄导致首条 sendReport()/transferOut() 失败）
