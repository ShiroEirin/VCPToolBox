## 核心结论
K2 指的是一套**「交接（handoff）」语义**：当一次请求需要把控制权从一段流交给另一段（工具循环、重入、续写）时，旧实现靠时序巧合，新实现给交接装了一道**带版本号的门**。两个仓库同一周各自对齐，说明这是双方约定的协议，而非单侧实现。

## handoffGate 源码事实
```js
function createHandoffGate(signal, { timeoutMs = 2000 } = {})
```
- 内部状态：`revision`（单调递增）、`last`、`ready`、`closed`、`waiters`（Set）。
- 中止处理：`signal.addEventListener('abort', onAbort, { once: true })`；`stopped()` = `closed || signal?.aborted`；中止时抛 `AbortError`，消息原文 `Request stopped during handoff`。
- 对外接口：`control({ action, handoffId, revision })`。

## 控制面错误码（逐字）
| 错误码 | 触发条件 |
|---|---|
| `INVALID_ACTION` | `action` 不是 `prepare_handoff` / `cancel_handoff` |
| `INVALID_HANDOFF` | `handoffId` 非字符串、为空、**超过 128 字符**，或 `revision` 不是 ≥1 的安全整数 |
| `REQUEST_STOPPED` | 请求已中止或门已关闭 |
| `STALE_REVISION` | 传入 `next < revision`（旧版本号迟到） |

## 为什么需要 revision
- 流式场景下同一个交接可能被重试或重发，若只看 `handoffId` 无法区分「新一次交接」与「旧消息重达」。
- `next === revision` 走幂等分支（不重复准备）；`next < revision` 直接判旧；`next > revision` 才推进。
- 即：**版本号做单调闸门，handoffId 做身份校验**，两者职责分离。
