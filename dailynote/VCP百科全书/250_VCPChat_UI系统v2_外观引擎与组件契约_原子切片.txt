一句话总结：把 UI 从「散装样式」升级为「三层架构」——外观引擎（用户偏好存储，36KB+）、组件清单（API 稳定性契约）、形变层（Web Awesome 封装）。

一、外观引擎（modules/ui-system/appearance-engine.js，14747 字节）

存储键：`vcpchat.appearanceProfile`。内置选项集均为 Object.freeze 白名单，实测 dimension：

| 维度 | 允许值 |
|---|---|
| density | compact / comfortable / relaxed |
| radius | square / small / medium / round / custom |
| typography | system / humanist / serif |
| fontScale | small / normal / large |
| contentWidth | full / centered |
| wallpaperScope | theme / panel / global |
| surface | solid / translucent / custom |
| surfaceEffect | **vibrancy / mica / acrylic / liquid** |
| shellRadius / composerRadius / sidebarRadius | tuned / follow / square / small / medium / round / custom |

要点：`tuned`（调校值）与 `follow`（跟随全局）是前缀选项，实现「分层微调但不失控」。

二、组件清单（component-manifest.js，全文实测）

每项为 Object.freeze `{ name, category, aliases, status, since }`，用两个工厂构造：`stable(name, category, aliases)` → since '1.0.0'；`candidate(name, category)` → since '1.1.0'。共 32 个组件：

- **stable（12）**：Button、Input、Textarea、Select、Range、SettingsSection、SettingsActionBar、Switch、Field、List（别名 ListItem）、Modal、Toast、SegmentedControl
- **candidate（19）**：IconButton、Checkbox、Badge、Alert、Card、Tabs、Toolbar、TableFrame、EmptyState、ConfirmDialog、InputDialog、Divider、Tooltip、Skeleton、Pagination、ScrollArea、AppPageShell、WindowControls、AsyncBoundary

的意义：把「哪些组件接口已冻结、哪些还可以改」写成可机读契约，而非人脑记忆。

三、形变层（Web Awesome，webawesome-runtime-manifest.js 全文实测）

```js
export const WEB_AWESOME_VERSION = '3.11.0';
export const WEB_AWESOME_LOCALE = 'zh-CN';
// 13 个组件：button、card、input、textarea、select、option、checkbox、
//            switch、tab、tab-panel、tab-group、dialog、tooltip
```

头注释原文点出关键约束：「Both the browser adapter and the offline closure generator consume this manifest, so adding a component necessarily changes the reproducible vendor output and its packaging gate.」——即**清单是唯一事实源**，浏览器适配器与离线闭包生成器共用，新增组件必然影响可重现构建产物与打包门禁。

八、2026-10-20 第25次上游合并：输入区模型切换保存队列修复（0cc86c28，PR #254）

- `modules/renderer/composerModelSelect.js`（+75/−29）：把原先的单一 `busy` 布尔量换成**按 Agent 分离的保存队列**。
  ```js
  const saves = new Map();
  let disposed = false;
  ```
  `choose()` 改为把目标模型写入对应 Agent 的 `state.pending`，由 `drainSaves(agentId, state)` 循环排空：
  ```js
  while (state.pending !== null) {
      const modelId = state.pending;
      state.pending = null;
      const result = await electronAPI.saveAgentConfig(agentId, { model: modelId });
      ...
  }
  ```
- **修的问题**：旧实现用 `busy` 挡住并发，**保存未完成期间的后续切换会被直接丢弃**（用户连点只生效第一次）。新实现把每次切换压入 `pending`，保存完成后继续排空，**最后一次意图胜出**。
- **回写策略更保守**：只在保存成功后回写选中项，且保留当前项的其它最新字段（`{ ...latest, model: modelId }`）；组件销毁后（`disposed`）不再发布结果，但仍继续排空以免留下悬挂 Promise。
- **失败可见**：保存失败调用 `window.uiHelperFunctions?.showToastNotification?.('切换模型失败: ...', 'error')` 并 `console.error('[ComposerModelSelect] 切换模型失败:', error)`。
- 新增 `tests/composer-model-select.test.mjs`（97 行）覆盖该队列语义；`tests/terminal-command-run-watch.test.js` +9 行（非 win32 平台 store 路径对齐，176e23b5）。
