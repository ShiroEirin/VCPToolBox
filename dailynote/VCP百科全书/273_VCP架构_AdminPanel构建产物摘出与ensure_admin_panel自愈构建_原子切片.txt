三、ensure_admin_panel.js 的双探针设计（头注释原文）

```text
跨平台 AdminPanel-Vue 前端静态资产校验与自愈构建中枢

核心职责：
1. 探针 A（物理与引用自洽）：检查 dist/index.html 是否存在，并反查其引用的主 JS/CSS 在磁盘是否真实存在（杜绝三层指纹错位与白屏）；
2. 探针 B（源码新鲜度比对）：比对 src/**, public/**, package.json, vite.config.ts 的最新 mtime 是否超过 dist；
3. 安全极速构建：在必要时调用 npm run build:no-type-check，强制覆盖 NODE_ENV=production，并注入 1024MB 堆上限防御 OOM。
```

三个设计点值得单独记：

| 点 | 内容 |
|---|---|
| **探针 A** | 不只查 `index.html` 在不在，还**反查它引用的主 JS/CSS 是否真实存在**——防的是「三层指纹错位」导致的白屏（HTML 引用了一个不存在的 hash 文件） |
| **探针 B** | 用 **mtime 比对**判断源码是否比产物新，覆盖 `src/**`、`public/**`、`package.json`、`vite.config.ts` 四类 |
| **构建策略** | 只在必要时构建；强制 `NODE_ENV=production`；注入 **1024MB 堆上限**防 OOM |

四、对部署的影响（重要）

1. **首次拉取后没有 dist**：必须跑一次 `npm run ensure:admin`（或 `build:admin`）才会生成管理面板静态资源，否则管理面板 404。
2. **构建需要 AdminPanel-Vue 的依赖**：脚本内部会调 `npm run build:no-type-check`，前提是 `AdminPanel-Vue/node_modules` 已存在（`--force` 不负责装依赖）。
3. **1024MB 堆**是硬编码值，低内存机器上构建仍可能失败。
4. **不再有「开箱即用」**：这是上游的明确取舍——用一次构建换仓库体积。

五、风险

1. **`dist` 已进 `.gitignore`**：任何本地对 dist 的改动都不会被 Git 追踪，也无法通过 stash 保护。
2. **探针 A 只校验主 JS/CSS**：懒加载 chunk 缺失不会被发现，仍可能白屏。
3. **mtime 比对在 clone 后失效**：Git 不保存 mtime，全新 clone 的源码 mtime 都是「现在」，可能误判为「源码更新」而触发一次多余构建（无害但耗时）。
4. 若部署流程依赖 `git pull` 后直接启动，必须补上 `ensure:admin` 步骤。
