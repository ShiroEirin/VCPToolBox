## 核心结论
这是对管理面「遍历攻击」（path traversal）的一次**统一收口**：上游没有逐路由补 `path.normalize` 判断，而是抽出一个唯一入口 `resolveSafePath`，把 Windows 语义强制施加到所有平台，让 14 个接受文件名/相对路径的 admin 与 dailyNotes 路由共享同一套边界。

## safeFilePath.js 的边界规则（源码逐条）
1. **字符集白名单外一律拒绝**：`/[\x00-\x1f\x7f<>:"|?*]/` 命中即抛错——含控制字符、`<>:"|?*`，天然挡掉 Windows 保留字符与 NTFS 备用数据流（`:`）。
2. **不做 URL 解码**：文件头注释原文 `Do not URL-decode here: Express has already decoded route parameters.`——避免二次解码绕过（`%252e%252e` 类攻击）。
3. **拒绝绝对路径与根起始**：`normalized.startsWith('/') || path.win32.isAbsolute(relative)` 直接抛错；即无论平台都按 Windows 绝对路径语义判定（`C:\`、`\\server\share`）。
4. **逐段校验**：空段、`.`、`..` 一律拒绝；**段尾为点或空格**（`/[. ]$/`）也拒绝——这是 Windows 会静默裁剪 `foo.` → `foo`、`foo ` → `foo` 导致的绕过点。
5. **Windows 设备名黑名单**：`/^(con|prn|aux|nul|com[0-9]|lpt[0-9])(?:\.|$)/i` 拒绝——防止写入设备名触发特殊行为。
6. **两档约束**：`singleSegment: true` 要求只有一段（用于「只接受文件名，不接受路径」的场景）；`allowRoot: true` 允许空相对路径解析为根本身。
7. **统一错误契约**：`invalidPath()` 产出 `code = 'UNSAFE_PATH'`、`status = 400`、`statusCode = 400`，上层无需各写映射。

## 为什么强制 Windows 规则
文件头注释原文：`Apply Windows rules on every platform so deployments have identical boundaries.`——同一份代码在 Linux 上不会因为 `/` 语义宽松而放宽，跨平台部署边界一致，安全行为可预期、可测试。
