# 一、定位

VCPChat 桌面端的专属分布式服务插件，让 VCPChat 桌面端与 VCPMobile 手机端进行可诊断、失败即停的双向增量同步。采用 **Double-Track 3-Tier（双轨三层）** 同步架构，底层设计多层级 Merkle 聚合指纹算法与 NDJSON 流式吞吐防线。

# 二、Wire 协议 1.4 硬切（2026-09-02 第13次上游合并）

- plugin-manifest version 1.2.0→**1.4.0**；README 徽章 Wire Protocol 1.4。
- **协议 1.4 硬切与兼容边界**（README 第102行起）：VERSION_CHECK { mobileVersion, protocolVersion: "1.4" } / VERSION_ACK { pluginVersion: "1.4.0", protocolVersion: "1.4" }。兼容性只由 protocolVersion 精确判断；pluginVersion 仅诊断信息。**旧 Wire 不保留别名或双栈**。
- Wire 1.4 使用**完整复合身份**（compound identities：ownerType/ownerId/topicId 三元组）、强类型状态、统一 ok/error 外壳。Phase 3 每个 Topic 的 decision 必须是判别联合之一：`{ ..., ok: true, ... }` 或 `{ ownerType, ownerId, topicId, ok: false, error: WireSyncError }`。
- 中央模式 Mobile→Desktop 消息同步会投影并写入 history.json；只修改 MobileSync 插件与 VCP-CDS 同步接口，不改模型调用/提示词/渲染。

# 二、同步范围

| 数据类型 | 物理路径 |
|---|---|
| 智能体 (Agent) | `Agents/{id}/config.json` |
| 群组 (Group) | `AgentGroups/{id}/config.json` |
| 话题 (Topic) | `Agents|groups` 下 topics 数组 |
| 消息历史 (Message) | `UserData/{parentId}/topics/{topicId}/history.json` |
| 附件 (Attachment) | Mobile→Desktop 按 hash 上传二进制；Desktop→Mobile 只同步合法元数据 |
| 自定义头像 (Avatar) | `Agents|groups/{id}/avatar.png`、`user_avatar.png` |

合并策略：**双向增量合并**，并发冲突以修改时间戳最新一端为准。

# 三、三阶段增量同步协议 V2

1. **Phase 1 轻量级索引扫描 (Reconcile)**：对比两端实体索引
2. **Phase 2 双哈希差分比对 (Double-Hash Merkle Diff)**：Merkle 聚合指纹定位差异
3. **Phase 3 NDJSON 流式吞吐 (Stream Ingestion)**：流式传输差异数据

# 六、安全防线
